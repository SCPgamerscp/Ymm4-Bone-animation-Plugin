# Ymm4-Bone-animation-Plugin

画像にボーンをつけて動かせるようにする、YukkuriMovieMaker4（YMM4）用の**図形プラグイン**です。

複数のパーツ画像（体・頭・髪・腕…）を親子関係のあるボーンで繋ぎ、
FK / IK・物理演算（揺れもの）・口パク / 目パチ連動でアニメーションさせられます。
いわゆる「切り抜き（Cutout）方式」の2Dボーンアニメーションです。

## できること

| 機能 | 概要 |
| --- | --- |
| **ボーン階層** | TreeViewでボーンを追加・削除・並べ替え。**ドラッグ＆ドロップで親子関係を変更**できます（循環参照は自動で拒否） |
| **FK（順運動学）** | 親ボーンを回すと子が付いてくる、通常の階層アニメーション |
| **IK（逆運動学）** | 手足の先端を目標位置へ動かすと、関節が自動で曲がります（2ボーン解析解 + CCD） |
| **Squash & Stretch** | 体積を保ったまま伸び縮み。漫画的な誇張表現に使えます |
| **キーフレーム補間** | 位置・回転・拡大率・不透明度・Z順・IKターゲットなどはすべてYMM4標準のアニメーション（キーフレーム）対応 |
| **プレビュー上のドラッグ操作** | プレビュー画面のハンドルを直接ドラッグしてボーンを移動・回転、IKターゲットを移動できます |
| **動的Z順** | Z順もアニメーション可能。「腕を体の後ろへ回す」といった前後の入れ替えができます |
| **差分画像切り替え** | 1つのボーンに複数の画像（差分）を登録し、番号で切り替え |
| **物理演算（揺れもの）** | 髪や服のボーンが親の動きに合わせて自動で揺れます（減衰バネモデル・角度制限つき） |
| **口パク連動** | YMM4の音声に合わせて口の差分画像を自動切り替え |
| **目パチ** | 一定間隔でまばたきの差分画像へ自動切り替え（シード値でタイミング調整） |
| **JSONテンプレート** | ボーン構造をJSONで保存し、他のアイテムやプロジェクトへ流用できます |

## 必要な環境

| 項目 | バージョン |
| --- | --- |
| YukkuriMovieMaker | 4.x（プラグインAPI対応版） |
| .NET SDK | **.NET 10 SDK** |
| OS | Windows 10 (build 19041) 以降 |
| IDE | Visual Studio 2022 以降 / JetBrains Rider（任意） |

> **補足**: プラグイン本体は `net10.0-windows10.0.19041.0` / WPF を対象とするため、

> ロジックの単体テストだけはLinux/macOSでも実行できます。

## ビルド方法

### 1. リポジトリを取得

```bash
git clone https://github.com/ailingmeng585-ship-it/Ymm4-Bone-animation-Plugin.git
cd Ymm4-Bone-animation-Plugin
```

### 2. YMM4のインストール先を設定する

YMM4本体のDLLを参照するため、**自分の環境のYMM4のパス**を教える必要があります。
リポジトリ直下の `Directory.Build.props.sample` をコピーしてリネームし、パスを書き換えてください。

```bash
copy Directory.Build.props.sample Directory.Build.props
```

`Directory.Build.props`:

```xml
<Project>
  <PropertyGroup>
    <!-- 末尾の \ を必ず付けてください -->
    <YMM4DirPath>D:\YMM4\</YMM4DirPath>
  </PropertyGroup>
</Project>
```

> `Directory.Build.props` は開発者ごとに異なるため `.gitignore` 済みです。コミットされません。

### 3. ビルド

```bash
dotnet build Ymm4-Bone-animation-Plugin/Ymm4-Bone-animation-Plugin.csproj -c Release
```

ビルドに成功すると、PostBuildイベントによって
`<YMM4DirPath>\user\plugin\Ymm4-Bone-animation-Plugin\Ymm4-Bone-animation-Plugin.dll` へ自動でコピーされます。

> **注意**: YMM4本体に同梱されているDLL（`YukkuriMovieMaker.*`, `Vortice.*`, `SharpGen.*`）は
> すべて `<Private>false</Private>` を指定しており、**プラグインと一緒に配布されません**。
> 同梱するとYMM4本体とバージョンがずれてプラグインの読み込みに失敗するためです。

## インストール

1. ビルドで生成された `Ymm4-Bone-animation-Plugin.dll` を用意します。
2. YMM4のインストールフォルダ内に `user\plugin\Ymm4-Bone-animation-Plugin\` フォルダを作ります。
3. その中に `Ymm4-Bone-animation-Plugin.dll` を置きます。
4. YMM4を再起動します。

```
YukkuriMovieMaker\
└─ user\
   └─ plugin\
      └─ Ymm4-Bone-animation-Plugin\
         └─ Ymm4-Bone-animation-Plugin.dll
```

## 使い方

タイムラインに **図形アイテム** を追加し、図形の種類から
**「2Dボーンアニメーション」** を選択するとプラグインが有効になります。

### 1. ボーンを組む

アイテム編集エリアの「ボーン階層」にツリーが表示されます。

| ボタン | 動作 |
| --- | --- |
| ＋ 追加 | 選択中のボーンと**同じ階層**にボーンを追加 |
| ＋ 子を追加 | 選択中のボーンの**子**としてボーンを追加 |
| － 削除 | 選択中のボーンを削除（その子は親に引き継がれます） |
| ▲ / ▼ | 描画順（リスト順）を前後に移動 |
| 親を解除 | 選択中のボーンをルートに戻す |

**ツリー上でボーンをドラッグ＆ドロップすると親子関係を変更**できます。
何もない場所へドロップするとルートになります。
自分自身の子孫を親にしようとした場合は循環参照になるため、確認ダイアログを出して変更を取り消します。

初期状態では「体 → 頭」の2ボーンが用意されています。

ボーン名の右側には有効な機能がマークで表示されます。

- `[IK]` … IKが有効
- `[揺れ]` … 物理演算が有効
- `[口]` … 口パク連動が有効
- `[目]` … 目パチが有効

### 2. パーツ画像を割り当てる

ツリーでボーンを選択すると、下部にそのボーンの設定が表示されます。

「差分画像」欄で `+` を押してスロットを追加し、`ファイル` から画像を選びます。
1つのボーンに複数の画像を登録でき、後述の差分切り替えで使い分けます。

**アンカーポイント**（`アンカーX` / `アンカーY`）は画像内での回転中心です。
`0,0` が画像の左上、`0.5,0.5` が中心、`1,1` が右下です。
たとえば腕であれば、肩の位置にアンカーを合わせると自然に回転します。

**長さ**は、そのボーンの子ボーンが接続される位置（＝ボーンの先端）です。
描画される画像のサイズとは独立しているので、関節の位置に合わせて設定してください。

### 3. アニメーションさせる

以下のプロパティはすべてYMM4標準のアニメーション（キーフレーム）に対応しています。
値の右側のボタンから中間点を打てば、自動で補間されます。

`X` / `Y` / `回転` / `拡大率X` / `拡大率Y` / `伸縮` / `不透明度` / `Z順` / `差分番号` /
`IKターゲットX` / `IKターゲットY` / `IK影響度`

また、**プレビュー画面上のハンドルを直接ドラッグ**しても操作できます。

- ボーンの**根本**の点 … ボーンを移動（親の回転を打ち消してドラッグ方向どおりに動きます）
- ボーンの**先端**の点 … ボーンを回転
- **赤い円** … IKターゲットを移動

「ボーンを表示」をオフにすると、ガイド線が描画されなくなります。

> **注意**: ガイド線は**動画出力にも含まれます**。書き出す前にオフにしてください。

> **Z順**はアニメーション可能な値です。たとえば「腕」のZ順を
> 体より小さい値へ動かすと、腕が体の後ろに回り込みます。
> 同じZ順のボーンはリストの順番どおりに描画されます（安定ソート）。

### 4. IKで動かす

腕や脚の**先端のボーン**（手先・足先）を選び、`IKを有効化` をオンにします。

| 設定 | 説明 |
| --- | --- |
| IKチェーン長 | 先端から何個の親ボーンまでを曲げるか。腕・脚なら `2`（2ボーン解析解が使われます） |
| IKターゲットX / Y | 先端を持っていきたい位置。キーフレーム対応 |
| IK影響度 | `0` でFKのまま、`1` で完全にIK。中間値でFKとIKをブレンドします |
| 曲がる向きを反転 | 肘・膝が逆向きに曲がるときにオンにします |

チェーン長が2の場合は余弦定理による解析解、3以上の場合はCCD法で解かれます。
ターゲットが届かない距離にある場合は、まっすぐ伸ばして最大限近づきます。

### 5. 揺れもの（物理演算）

髪や服・アホ毛などのボーンで `物理演算を有効化` をオンにします。

| 設定 | 説明 |
| --- | --- |
| 硬さ | 大きいほど元の角度へ素早く戻ります |
| 減衰 | 大きいほど揺れがすぐ止まります |
| 慣性 | 親の動きをどれだけ揺れに変換するか |
| 重力 | 下方向へ引っ張られる強さ |
| 角度制限 | 元の角度からこの角度以上は曲がりません（跳ね返ります） |

親ボーンの移動のうち、**ボーンの軸に対して垂直な成分だけ**が揺れになります。
髪の毛が伸びている方向へ引っ張っても揺れないのは物理的に正しい挙動です。

全体設定の `物理演算を有効化` をオフにすると、すべての揺れが止まります。

> タイムラインをシークすると内部状態がリセットされます。
> 連続再生していない位置へジャンプしたときに揺れが暴れるのを防ぐためです。

### 6. 口パク・目パチ

**口パク**: 口のボーンで `口パク連動を有効化` をオンにし、
`口パクスロット名` に切り替えたい差分の名前をカンマ区切りで指定します。

```
閉じ, 半開き, 開き
```

音声の大きさに応じて左から右のスロットへ切り替わります。
`口パク拡大率` を上げると、開き具合に応じてボーンが少し拡大します。

**目パチ**: 目のボーンで `目パチを有効化` をオンにし、
`目パチスロット名` に指定します。

```
開き, 半目, 閉じ
```

`まばたき間隔`（秒）ごとに `まばたき時間`（秒）だけ閉じます。
全体設定の `目パチシード` を変えると、まばたきのタイミングがずれます。
複数キャラを並べるときにシードを変えると、同時にまばたきしなくなります。

> 口パク・目パチのどちらも無効なボーンでは、`差分番号` の値がそのまま使われます。
> 優先順位は **手動指定 → 口パク → 目パチ** です。

### 7. テンプレートの保存・読み込み

「テンプレート」欄の `保存` を押すと、現在のボーン構造をJSONファイルとして保存できます。
`読み込み` で復元できます（現在のボーンは置き換えられるため、確認ダイアログが出ます）。

作ったキャラの骨組みを別プロジェクトで使い回したいときに便利です。

## アーキテクチャ

YMM4やDirect2Dに依存する部分と、純粋な計算ロジックを明確に分離しています。

```
Ymm4-Bone-animation-Plugin/
├─ Core/                    ★ YMM4・Direct2D非依存（テスト可能）
│  ├─ MathHelper.cs           角度・ベクトル・行列のユーティリティ（NaN安全）
│  ├─ BonePose.cs             1フレーム分のローカル姿勢 + Squash&Stretch行列生成
│  ├─ BoneDefinition.cs       ボーンの静的定義（画像スロット/物理/口パク/目パチ/IK設定）
│  ├─ Skeleton.cs             ボーン階層。循環参照を拒否するSetParent・トポロジカル順序
│  ├─ BoneTransform.cs        評価結果（ワールド行列・Z順・使用中スロット）
│  ├─ SkeletonEvaluator.cs    FK → IK → 物理 → Z順ソート のパイプライン
│  ├─ SkeletonTemplate.cs     JSON永続化用のDTO
│  └─ Kinematics/
│     ├─ IkSolver.cs          2ボーン解析解 + CCD法
│     ├─ PhysicsSimulator.cs  減衰バネによる揺れもの
│     └─ SlotSelector.cs      手動 / 口パク / 目パチ による差分選択
│
├─ Shape/                   ★ YMM4プラグインAPI連携
│  ├─ BoneShapePlugin.cs      IShapePlugin（プラグインのエントリポイント）
│  ├─ BoneShapeParameter.cs   ShapeParameterBase（設定項目・SharedData）
│  ├─ BoneShapeSource.cs      IShapeSource2（Direct2D描画 + プレビュー制御点）
│  ├─ BoneItem.cs             Animatable（キーフレーム対応のボーン設定）
│  └─ BoneImageSlot.cs        差分画像1枚分の設定
│
├─ Rendering/
│  └─ BoneImageCache.cs       パスをキーにした画像キャッシュ（失敗もキャッシュ）
│
└─ Views/                   ★ WPF編集UI
   ├─ BoneTreeEditor.xaml(.cs)      ドラッグ＆ドロップ対応のボーン階層TreeView
   ├─ BoneTreeEditorViewModel.cs    追加・削除・並べ替え・親子繋ぎ替え
   ├─ BoneTreeNodeViewModel.cs      ツリーの1ノード
   ├─ ImageSlotEditor.xaml(.cs)     差分画像スロット一覧エディタ
   ├─ TemplateIoEditor.xaml(.cs)    JSONテンプレートの保存・読み込み
   └─ *Attribute.cs                 PropertyEditorAttribute2 の実装
```

### 評価パイプライン

毎フレーム、`SkeletonEvaluator.Evaluate()` が以下の順に処理します。

```
1. FK      親から子へトポロジカル順に走査し、ワールド行列を合成
             child.World = local * 親の先端への平行移動 * parent.World
2. IK      IK有効なチェーンを解き、FK結果へ影響度でブレンド
3. 物理     揺れもの設定のあるボーンへ減衰バネを適用し、子孫へ伝播
4. Z順ソート 奥→手前に安定ソート（同じZ順ならリスト順）
```

### 設計上の判断

- **Core層をYMM4から完全に分離**
  ボーン計算・IK・物理・JSON永続化のロジックはYMM4のDLLを一切参照しません。
  これによりWindows/YMM4がなくても `dotnet test` でロジックを検証できます。

- **循環参照を構造的に防ぐ**
  `Skeleton.SetParent()` が自己参照・循環を検出して拒否します。
  UI側はその戻り値を見て変更を取り消すため、無限ループでフリーズすることがありません。
  万一データが壊れていても `GetTopologicalOrder()` は未訪問ノードを末尾に追加して停止します。

- **Direct2Dリソースは使い回す**
  プレビュー中は `Update()` が絶えず呼ばれます。ブラシやエフェクトを毎フレーム生成すると
  すぐに重くなるため、コンストラクタで作成して使い回します。
  Effectから取得した `Output` は必ず `Dispose` し、入力は `SetInput(0, null, true)` で解放します。

- **NaN・発散への防御**
  ユーザーが極端な値を入れたりゼロ除算が起きても描画が壊れないよう、
  行列生成前に `BonePose.Sanitized()` で値を検証し、物理演算にも
  デルタタイムのクランプと角度制限を入れています。

## テスト

Core層のみを対象とした単体テスト（xUnit・56件）があります。
Core層はYMM4に依存しないため、**Linux/macOSでも実行できます**。

```bash
cd tests/Ymm4-Bone-animation-Plugin.Core.Tests
dotnet test
```

テスト対象:

| ファイル | 内容 |
| --- | --- |
| `SkeletonTests.cs` | 階層操作・循環参照の拒否・トポロジカル順序・チェーン取得 |
| `EvaluatorTests.cs` | FK合成・不透明度の乗算・Z順ソート・Squash&Stretch |
| `IkSolverTests.cs` | 2ボーンIKの到達性・届かない距離・曲げ方向反転・影響度ブレンド |
| `PhysicsAndSlotTests.cs` | 揺れの発生条件・角度制限・差分選択の優先順位・目パチの決定性 |
| `TemplateTests.cs` | JSONの往復変換・壊れたJSONの扱い・角度演算 |

> このテストプロジェクトは `net8.0` を対象とし、
> `Core/**/*.cs` を直接 `<Compile Include>` することでYMM4への依存を避けています。
